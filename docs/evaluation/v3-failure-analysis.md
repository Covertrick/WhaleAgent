# 测试集失败

288 次全部留在分母里。下面的原因按出现次数计，一条轨迹可以有多个原因。每个蓝图最多 4 次失败（2 个变体 × 2 次）。

## 原因

| 策略 | 最常见的原因 |
| --- | --- |
| react@1 | 草稿缺字段 15 次，过期写入 1 次。没有“该有提醒却没有” |
| egaa@2 | 该有提醒却没有 14 次，草稿缺字段若干，过期写入 4 次 |
| Always Refresh | 该有提醒却没有 14 次，过期写入 14 次，草稿缺字段若干 |

两种计划策略缺提醒的次数相同。刷新规则没有把提醒补出来。计划没写 `schedule.reminder`，或者写了但没有执行成功。

## 蓝图

全部 4 次都失败、而 ReAct 没有全灭的例子：

- `s3_chain_forbid`、`s3_join_converge`、`s3_parallel_one_clock`：没有通知，时间或状态在第一次阅读后变化。计划策略更常交旧值，或没交提醒。
- `s5_fanout_one_field`：待办草稿不能含新名字，负责人备忘必须含新名字。整份原文拷进待办会触发禁止词。
- `s2_join_watermark`：两份时间相同才提醒，水印不能进入结果。计划策略 4 次都失败，ReAct 没有失败。
- `s5_parallel_keep_drafts`：两段说明保持原文，提醒用新时间。计划策略 4 次都失败。

三边都是 4 次失败的是 `s3_fanout_owner_hidden`。名单上的负责人会悄悄更换，没有通知。这一题没有策略做对。

ReAct 失败集中在草稿缺字段，例如 `s1_fanout_owner` 3 次、`s1_parallel_second_clock` 3 次、`s3_fanout_owner_hidden` 4 次。过期写入只有 1 次。

没有因为失败而改评分器或删题。
