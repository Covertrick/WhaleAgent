# 失败归到哪一层

v2 的失败归到读节点不收口和计划 token。v3 的正式测试把另一层分开了。

计划层：EGAA 和 Always Refresh 在测试集上各有 14 次该有提醒却没有。次数相同，所以这不是“写前刷新不够”能解释的。计划提示只允许 `value_from` 指向一份已读事实。目标要合并两份原文，或只要其中一句时，计划策略会整份拷贝，然后缺字段或踩到禁止词。ReAct 没有这条限制，它的失败里没有缺提醒。

证据层：同样是计划策略，Always Refresh 有 14 次过期写入，EGAA 有 4 次。成功率差的区间不含 0。这一层 EGAA 更好，代价是观察更多，不是更少。单次 token 几乎一样，因为计划提示相同，提示 token 都是 31200。

费用层：相对 ReAct，EGAA 的 token 少一个数量级，区间不含 0。相对 Always Refresh，省下的是每次成功 token，不是每条轨迹的 token。成功数更高，分母变了。

整图重规划只在开发集跑过。它把计划调用从 24 加到 36，成功数仍是 10/24，没有超过局部修复。它没有进入测试集。

紧凑计划没有做真实模型对照。不能把这次 token 下降说成提示压缩的结果。下降来自计划请求关闭了思考：否则当前模型会把 4000 token 花在推理上，JSON 被截断。`max_tokens` 没有降低。
