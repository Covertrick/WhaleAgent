# 项目资料任务：决策环步骤

演示任务不要求用户写出 `vN` 或内部事实键。用户可以在同一条消息里写明公开事实。工具若返回 `EVIDENCE` 块，以工具块为准。

> 帮我整理最近的项目会议资料，生成待办清单写进 Vault，根据最新截止时间创建提醒。遇到信息冲突先核实，完成后告诉我哪些操作成功、哪些还需要确认。

公开事实示例：

```text
帮我整理项目会议资料，写入待办并创建提醒。
资料 v1：周一例会纪要，待办是整理实验记录
截止 v1：2026-11-20T10:00:00+08:00
```

计划节点仍使用 `read_fact` / `write_fact`。应用层把它们翻译成下面的工具。算法包看不到这些工具名，也看不到评分器里的隐藏真值。

| 步骤 | 工具 | 决策 |
|------|------|------|
| 读会议资料 | `search_vault` | 得到可排序版本或同一来源的内容哈希后，草稿分支不再为了写入而重读 |
| 写待办草稿 | `write_vault_draft` | 可重写。正文来自已见证据，不调用模型扩写 |
| 读截止时间 | `search_vault` | 创建提醒前再读一次。原因码 `POTENTIALLY_STALE` |
| 只重读变化的事实 | `search_vault` | 收到相关变化通知时只重读该事实。原因码 `FACT_CHANGED`。已完成草稿保持完成 |
| 创建提醒 | `schedule_reminder` | 不可逆。使用当前 `VALID` 的截止时间 |
| 回执未知 | `schedule_list` | `schedule_reminder` 在同一次 Run 里只出现一次，随后查询已有提醒并停止 |
| 核对 | 信念里的当前证据 + 已确认回执 | 隐藏世界和评分器不参与这一步 |

版本规则：`v` 加整数可以直接比较。SHA-256 不能排序。同一来源重新读到相同哈希时保持原修订；内容变了才登记下一个修订。两个来源的值不一致，或文本没有来源标识时，证据保持 `UNKNOWN`，不创建提醒。
